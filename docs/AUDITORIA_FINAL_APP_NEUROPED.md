# Auditoria Final do App NeuroPed

Data: 2026-06-07

## Objetivo

Auditar o app atual em busca de falhas de funcionamento, build, navegação, segurança local, filtro, números exibidos, área dos pais e deploy.

## Estado operacional

- Repositório: `jadsonfraga/neuroped`
- Branch auditada: `main`
- Último commit antes desta documentação: revisão de `main.tsx` para evitar referência de tipo sem import explícito.
- CI remoto: sem status retornado pelo conector no momento da consulta.
- Runtime npm local: indisponível neste ambiente.

## Verificações realizadas por código

### 1. Scripts de validação

O `package.json` contém os scripts exigidos:

- `npm run check`
- `npm run build`
- `npm run validate:catalog`
- `npm run test:clinical`
- `npm run verify`

Estado: scripts existem, mas não foram executados neste ambiente.

### 2. Gate inicial

O app usa `PasswordGate` antes de renderizar `App` em `client/src/main.tsx`.

Falha encontrada: havia risco de referência de tipo sem import explícito no `GateCompat`.

Correção aplicada: importação explícita de `ReactNode`.

Estado: corrigido por revisão de código.

### 3. Gate duplo

O `App.tsx` ainda contém `LocalUnlockGate` interno. Para evitar segundo bloqueio após o PIN global, `main.tsx` sincroniza a sessão liberada pelo gate principal com o fluxo legado.

Estado: compatível, porém ainda há débito técnico.

Correção ideal futura: remover o `LocalUnlockGate` legado de `App.tsx` e deixar apenas o `PasswordGate` global.

### 4. Rotas principais

Foram conferidas no `App.tsx` e na navegação:

- `/`
- `/filtro`
- `/pant`
- `/pacientes`
- `/portal-familia`
- `/portal-familia/novidades`
- `/portal-familia/acesso`
- `/orientacao-parental`
- `/inventarios-escola`
- `/farmacologia`
- `/satisfacao-medicacao`
- `/ajuda`
- `/escalas-neuropsiquiatria`

Estado: rotas existem no roteador.

### 5. Números fixos

Busca realizada por padrões antigos:

- `45+`
- `75+`
- `142`
- `450+`
- `495+`
- `500+`

Estado: busca não retornou achados ativos após correções. A Central de Ajuda foi atualizada para usar `appMetrics`.

### 6. Filtro Clínico Inteligente

O filtro usa:

- `allScales`
- `filterableCatalog`
- `noCostWorldScales`
- tentativa de carregar registro remoto de 100 escalas mundiais

Saída obrigatória mantida:

- Ouro
- Prata
- Bronze
- Teste Direto
- Questionário Escolar

Estado: lógico por revisão de código; teste visual pendente.

### 7. Base mundial remota

Falha potencial: o filtro tenta carregar JSON remoto em `raw.githubusercontent.com`.

Mitigação já existente: se falhar, cai para `fallback` e mantém `noCostWorldScales` local.

Estado: aceitável, mas dependente de teste em navegador.

### 8. Área dos pais

A navegação tem grupo próprio `Pais / Psicoeducação` com:

- Portal dos pais
- Orientação parental
- Novidades para famílias
- Política de acesso
- Questionário escolar
- CAA

Estado: estrutura separada por código.

Risco remanescente: auditoria visual rota por rota ainda necessária.

### 9. Portal da Família

O Portal da Família busca documentos por API quando há código de acesso.

Risco: em deploy estático sem backend, documentos liberados podem falhar.

Mitigação recomendada: manter mensagem clara de que a área educativa funciona e documentos individualizados exigem backend/API.

Estado: parcialmente funcional, dependente de backend para documentos.

### 10. Ruído de gerador e logs

Busca por padrões de ruído:

- `created by`
- `Criado por`
- `gerado por`
- `Generated by`
- `lovable`
- `bolt`
- `v0`
- `TODO`
- `FIXME`
- `console.log`
- `alert(`

Estado: sem achados retornados pela busca.

## Falhas corrigidas nesta auditoria

1. Tipo `React.ReactNode` em `main.tsx` sem import explícito.
2. Números manuais na Central de Ajuda corrigidos anteriormente para `appMetrics`.
3. Botão de bloqueio local ajustado anteriormente para limpar sessão real e forçar rechecagem.
4. Catálogo suplementar criado anteriormente para itens aplicáveis fora de `allScales`.
5. Grupo `Pais / Psicoeducação` separado da área clínica.

## Falhas ainda não plenamente resolvidas

1. `LocalUnlockGate` legado ainda existe em `App.tsx`.
2. Testes npm não foram executados neste ambiente.
3. Não há evidência de CI verde no último commit consultado.
4. Não há teste visual real em navegador neste ambiente.
5. Portal da Família depende de backend para documentos individualizados.

## Comandos obrigatórios para validação final

```bash
npm run check

npm run test:clinical
```

## Teste manual obrigatório

1. Abrir app em produção.
2. Inserir PIN master.
3. Confirmar abertura da home.
4. Clicar em Bloquear acesso.
5. Recarregar página.
6. Confirmar que volta ao gate.
7. Abrir `/filtro`.
8. Buscar: autismo, tdah, ansiedade, sono, escola, linguagem, aprendizagem, depressão, trauma, medicação.
9. Confirmar cinco blocos em cada busca.
10. Abrir Portal dos Pais e verificar que não há dados sensíveis expostos.

- build verde;
- validação de catálogo;
- teste visual real;
- deploy confirmado.

Estado atual: auditoria por código concluída, correções críticas aplicadas, validação executável pendente.
